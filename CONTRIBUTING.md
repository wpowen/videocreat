# Contributing

Thanks for helping improve the project.

## Before opening a pull request

1. Keep changes focused and avoid committing generated output, local runtime state, browser traces, credentials, or private media.
2. Add or update a targeted self-test when behavior changes.
3. Run syntax checks for changed JavaScript files and the smallest relevant validation scripts.
4. Confirm that every new media asset has a documented source and redistribution right.
5. Run a secret scanner against both the working tree and the commits in your branch.

## Pull request notes

Describe the user-facing outcome, the affected workflow, the validation performed, and any remaining limitations. Security reports should follow `SECURITY.md` instead of using a public pull request or issue.
