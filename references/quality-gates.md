The batch readiness command must fail by default when any target remains in `needsRegeneration`; `--allow-pending-native-targets` is permitted only for partial review packages and must be reported as not all-size upload-ready.

## Incremental Repair Required Files

When a package is repaired through a localized incremental path instead of a full rerun, the revision package must add these files on top of the copied base package:

- `workflow/incremental-edit-lineage.json`
- `workflow/incremental-timing-summary.json`
- `logs/incremental-qc.json`
- `logs/incremental-ffprobe.json`
- `logs/incremental-blackdetect.log`
- `logs/incremental-volumedetect.log`
- `screenshots/incremental-base-target-scene.png`
- `screenshots/incremental-patched-target-scene.png`
- `renders/final.base.mp4`
- `renders/final.mp4`

`workflow/incremental-edit-lineage.json` must name the base project, output project, target scene id/order/start/end, dirty nodes, reused nodes, and output evidence paths. `workflow/incremental-timing-summary.json` must record stage/category durations so the repair cost can be compared with the full workflow. A copied full-run `logs/qc.json` is allowed as inherited context, but it is not valid proof that the incremental repair itself passed.

## Media Checks

Pass criteria for the local video workflow:

- Duration: matches the generated plan derived from the actual narration/content length, unless the user explicitly requested a fixed duration.
- Runtime configuration: `workflow/runtime-config.json` exists, records `assets/runtime-defaults.json` or the explicit `CODEX_VIDEO_WORKFLOW_CONFIG` override as the source, and proves the resolved image, voice, material, cover, and frame-limit policies. Ambient environment capabilities such as `OPENAI_API_KEY` must not silently change the default image path; real Image 2 API usage requires `--image-source image2` or a brief field that explicitly chooses it.
- Generation mode contract: `workflow/generation-mode-contract.json` exists, names `full-auto` and `semi-auto` as supported product modes, keeps ordinary topic/script intake on `semi-auto` / configuration-page default, records that `full-auto` requires explicit user/caller opt-in, records the horizontal-by-default rule for explicit full-auto, defines semi-auto prepare/configure/page-edit/compose stages, and includes the page-level TDS edit contract. Semi-auto/custom runs must also write `semi-auto-config.html` and `workflow/semi-auto-config.json` before final composition.
- Semi-auto cover configuration: `semi-auto-config.html` must include a cover design module with cover generation enabled by default, one large final/sample-cover preview, click-to-open large preview, and one compact right-side options panel with visible controls for every supported cover resolution target recorded in `workflow/cover-size-selection.json` / `workflow/cover-design.json.resolutionPresets`. The preview carousel must bind each target to its exact `cover/*` asset when present and show upload-ready vs `needs-native-target-ratio-image2` status instead of hiding missing native ratio work. The configuration page must not render old bulky methodology, template/status, final-rule, or bottom duplicate resolution blocks; those details stay in workflow artifacts.
- Resolution: must match the selected platform canvas. Horizontal review defaults to `1920x1080`; this remains the default unless the brief explicitly asks for portrait/`9:16`, Douyin, TikTok, YouTube Shorts, Reels, or generic vertical short-form/短视频 output. Ordinary hooks, opening beats, first-three-second promises, or口播 wording alone must not switch the canvas to vertical. Explicit vertical short-form defaults to `1080x1920`.
- FPS: 30 preferred.
- Video codec: H.264 or a locally playable MP4 codec.
- Audio: present, AAC or compatible MP4 audio.
- Audio/video sync: stream durations should be effectively equal after muxing, normally within one frame plus encoder tolerance; the QC log must report the audio/video duration delta.
- Opening visual/audio: by default the MP4 must start directly on the first content scene and narration must start at 0s. If the user explicitly requests an in-video opening cover, narration must still start at 0s and the cover must overlap the first spoken scene. QC must fail silent cover pre-roll unless the user explicitly requested a silent title-card opening.
- Final audio loudness: `volumedetect` must show audible口播 volume, with mean volume not below `-36 dB` and max volume not below `-18 dB`; prefer a normal spoken-video range around `-30 dB` to `-18 dB` mean volume.
- Voice backend: Chinese videos must use `cosyvoice_local` or `melotts_local` unless `--allow-say-fallback` was explicitly used and reported as degraded.
- MeloTTS parameters: Chinese runs must use language `ZH`, CPU device by default, and a recorded speed value, normally around `0.95`.
- Chinese pronunciation preflight: analyze the complete `script/narration-spoken.txt` before segmentation and synthesis. The preflight must record every candidate occurrence, context, selected tone3 pinyin, source, unresolved count, narration hash, and effective-plan hash. Unresolved occurrences fail final generation unless an explicitly degraded review run uses `--allow-unresolved-pronunciations`.
- Chinese polyphone application: `workflow/effective-pronunciation-plan.json.phrases` must be synthesis-ready, non-empty, and identical to the analyzed effective entries. Controlled phrases must be injected into both `pypinyin` and `jieba`, pass the real MeloTTS frontend G2P probe, remain intact inside one TTS cue, and write `workflow/pronunciation-application-verification.json`. The application artifact must prove `pronunciationLoaderActive: true`, a positive `loadedPronunciationEntries`, and `loadedPronunciationHash === pronunciationPlanHash`. A controlled plan locks `auto` to `melotts_local`; an empty plan, hash mismatch, inactive loader, or backend failure must block instead of silently using default pronunciation or falling back to an unverified backend.
- Pronunciation cache integrity: `workflow/voice-subtitle-manifest.json` must record `pronunciationNarrationHash` and `pronunciationPlanHash`. Audio reuse and shared segment caches must invalidate when either the spoken manuscript or effective pronunciation plan changes.
- Voice direction: `workflow/voice-direction.json` exists and names speech style, pace, tone, pause policy, and sentence completeness rules.
- Punctuation pause policy: `workflow/voice-direction.json` records `pauseDurations.commaLikeSeconds` as `0.5` and `pauseDurations.sentenceEnd` as `tts-default`; `script/narration-spoken.txt` must not add a newline immediately after comma-like punctuation (`，`, `,`, `、`).
- Audio dynamics: final narration should use compression, dynamic normalization, limiting, or loudness normalization when volume varies noticeably; the manifest must record the filter chain when used.
- Spoken narration: `script/narration-spoken.txt` exists and uses sentence-end or semantic-beat line breaks for TTS pauses when口语化/conversational is requested.
- Sync timecode: `workflow/sync-timecode-plan.json` exists and defines the shared timing source for narration, subtitles, main visual scenes, visual rhythm events, progress indicators, and opening/cover continuity. Long口播 should use ASR/forced-alignment evidence when available.
- Content presentation design: `workflow/content-presentation-design.json` exists and defines topic type, audience state, content jobs, hierarchy, display logic, visual metaphor, layout system, motion purpose, aesthetic bar, and reject list.
- Page decision contract: `workflow/page-decision-contract.json` exists and answers five questions for every scene/page: what content appears, how that content is designed, how MP4-safe interaction/state is represented, how animation is selected/timed, and which planner/design/motion/render/QC layer owns the decision.
- Retention structure contract: `workflow/retention-structure-contract.json` exists and uses the RETAIN model for every final-quality run, not only vertical short-form videos. It must bind first-frame relevance, the first-30-second viewing promise, one visual subject per scene, thinking-aid purpose, attention rhythm, information proof cadence, progress cues, ending payoff, and production-phase ownership from brief through QC. `logs/qc.json` must pass `retentionStructureContractPresent`, `firstFrameRetentionPromisePresent`, `firstThirtySecondContractPresent`, `evidenceCadencePlanned`, and `progressAndPayoffPlanned`.
- Theme readability: `workflow/theme-readability-audit.json` exists and passes. It must record the selected background owner, per-scene `themeKey`, background, ink, caption band, text/caption contrast ratios, and the dark-background strategy/reason when a full-stage dark theme is used. Default final videos use light, warm, neutral, paper, glass, or product-surface backgrounds. Valid dark strategies require explicit user opt-in or locked scene intent: explicit dark style, presenter/studio focus, typed black-white opener, or locked scene style. The words `口播`, `口播稿`, `钩子`, `前三秒`, `3 秒`, `短视频`, `AI`, `代码`, `技术`, `系统`, or `数据` alone must not route a scene to a full black/charcoal stage. If dark is used, it must include a premium foreground/background material strategy rather than a flat black canvas.
- Cover design: `workflow/cover-design.json` exists and states `defaultCoverEngine: "image2-integrated-typography-cover"`, `sharedContentPromiseMultiPlatformVariants: true`, `platformSpecificDesignsGenerated: true`, selected/pending Image 2 integrated cover evidence, master/shared cover concept, inferred `contentCategoryStrategy`, `platformCoverStrategies`, `competitorResearchPlan`, selected composition template, composition reason, composition blueprint, UI quality bars, research synthesis, resolution presets, viewer decision, cover promise, curiosity gap, hook text, payoff text when used, visual subject, emotional signal, composition, typography, contrast, small-preview test, thumbnail readiness, content truth, title/script-derived click motivation, 100-point cover QA score, root output copies, raster size evidence, and reject list. `workflow/cover-image2-prompts.json` must exist for every cover package and should contain Image 2 integrated-cover prompts for active platform strategy variants by default. `workflow/context-image2-cover-requests.json` must also exist in Codex App cover packages so Context Image2 / `image_gen` generation uses the core cover logic rather than ad hoc prompts.
- Bounded Image2 parallelism: when a Context Image2 or Image2 jobs manifest declares concurrent generation, it must include `parallelGenerationPolicy.allowed`, `defaultMaxConcurrency`, `maxConcurrency`, a stable `consistencyGroup` when identity/style continuity matters, and request-level stable ids plus expected outputs. Parallel generation may speed up provider calls, but ingestion, artifact mutation, and final QC must preserve deterministic request-to-output mapping.
- Cover/video lane independence: `workflow/cover-parallel-execution.json` must show the core cover lane completed or failed independently from TTS, native-page assembly, and final MP4 render. Personal-IP native-final blockers must not prevent `workflow/cover-design.json`, `workflow/cover-image2-prompts.json`, `workflow/cover-size-selection.json`, and `workflow/context-image2-cover-requests.json` from being written by the core cover engine.
- Cover Image 2 QC: `workflow/cover-image2-qc.json` must not mark `finalCoverQualityEligible: true` while `generatedBitmapInspectionStatus` is `pending-human-or-vision-review`; pending Codex/Image2 bitmaps are review-pending only until a human or vision review result is recorded.
- High-click knowledge cover contract: for knowledge/tutorial, creator-methodology, AI/tool/workflow, video-operation, and short-video profile covers, `workflow/cover-design.json.highClickCoverPromptContract.methodologyVersion` and every `workflow/cover-image2-prompts.json.prompts[].highClickCoverPromptContract.methodologyVersion` must equal `high-click-knowledge-cover-v1`. The generated Image 2 prompt must include the topic/audience/selling point/big-title derivation, horizontal or vertical native composition, original presenter or strong proof subject, before-vs-after proof module when truthful, growth/warning/action signal, strict visible-text whitelist, premium 3-4 color rule, and negatives against cheap marketing posters, PPT/configuration/workflow mocks, platform logos, watermarks, QR codes, random text, and untruthful clickbait.
- Cover Image 2 QC: `workflow/cover-image2-qc.json` exists and records prompt-quality checks, bitmap presence, `integratedTypographyAssetPresent`, required visual bars, blocker list, `reviewFallbackOnly`, `contextImage2Required`, `contextImage2RequestFile`, and `finalCoverQualityEligible`. Final-quality cover claims require `promptQualityPass: true`, a real selected Image 2/Codex bitmap with integrated Chinese typography, and no blockers. `image2-dryrun`, subject-only bitmap, SVG-only, or deterministic overlay fallback can be reviewed, but must not be reported as final-quality cover output. When a real bitmap is missing or not inspected, `workflow/context-image2-cover-requests.json` must remain the required Context Image2 handoff for completion.
- Platform submission cover identity: the cover uploaded in the platform publishing form is an independent artifact. Final video QC requires `primaryPlatformUploadCoverReady: true` and `platformSubmissionCoverReady: true`, backed by a `completed` Context Image2/`image_gen` request with `purpose: "platform-submission-cover"`, `videoInternalCover: false`, passed human/vision inspection, and a real upload-ready output under `最终成品/`. An in-video opening cover, first frame, native-page review cover, pending request manifest, SVG/HTML fallback, or review raster cannot satisfy this gate. Validate it with `scripts/validate-platform-submission-cover.mjs --out <output-dir>`.
- Aesthetic brief: names visual territory, taste goal, avoid list, composition/color/type/imagery/motion rules, and skill/capability routing.
- UI/UX Pro Max design intelligence: `workflow/ui-ux-pro-max-design-intelligence.json` exists and records `active`, `partial`, or `unavailable` status. When active, its design-system, style, typography, UX, and HTML/Tailwind recommendations must be treated as pre-render art-direction evidence and mapped into `workflow/aesthetic-brief.json` / `workflow/content-presentation-design.json`; it must not replace renderer, timing, rights, voice, image2, cover, or QC contracts.
- Motion template selection: `workflow/motion-template-selection.json` exists and names selected template, source platform logic, motion jobs, semantic binding, implementation path, fallback policy, verification, and reject list.
- Galacean visual effects: when visual effects, particles, fireworks, 2D/3D effects, energy beams, magical UI accents, premium transitions, risk scans, product activation, or payoff effects are active, `workflow/galacean-effects-plan.json` exists and references `assets/galacean-effects-capability-catalog.json`. The plan must record selected and rejected scene effects, semantic job, placement/layer order, avoid regions, subtitle-safe policy, timecode binding, intensity, asset source/license/provenance, fallback, and required screenshots/motion evidence. `workflow/external-capability-fusion-plan.json` must record Galacean as a bounded borrowed capability, and `workflow/visual-asset-manifest.json` must include every selected effect asset. Exact viewer-facing Chinese text must remain in deterministic HTML/SVG/CSS or subtitle layers, not only inside canvas/WebGL textures.
- Motion style template selection: `workflow/motion-style-template-selection.json` exists and references `assets/motion-style-template-library.json` plus `references/motion-style-template-design-spec.md`. It must bind every scene to a reusable template id, content kind, page job, layout blueprint, deterministic typography owner, semantic motion contract, data accuracy rule, asset task contract, sub-agent handoff, caption safe area, and reject list. The selected template may not differ only by color and must not leave Planner, TTS timing, template design, data/material, and Renderer/QC agents making conflicting scene decisions.
- Remotion motion primitives: `workflow/motion-template-selection.json` contains `remotionMotionPrimitives` with source plugin, frame-driven timeline owner, easing rules, transition discipline, and one scene primitive per design scene. `workflow/motion-grammar-plan.json` mirrors the primitive on each component as `remotionPrimitive`.
- Visual planner: design plan exists and names video type, template kit, per-scene shot template, image role, and motion language.
- Image assets: each scene has an inserted original illustration/image asset and an image2-compatible prompt, whether the run uses local SVG fallback, selectively approved Codex built-in `image_gen` bitmaps, or direct Image2 API output. `workflow/image-generation-strategy.json` must record the tool/provider route, prompt contract, scene-level image jobs, and any Image2 explainer-board route. `workflow/visual-relevance-audit.json` must prove the prompt and selected visual are bound to scene narration/headline keywords rather than generic decoration.
- Media routing: `workflow/media-routing-plan.json` exists and records per-scene Image2/Codex generation status, dryrun prompt-only status, free-commercial素材/provider search status, selected assets, provider attempts, blockers, and whether the route is `auto` or `required`. Required scene images or required free-stock素材 cannot pass with prompt-only/local fallback evidence.
- Image prompt methodology: `workflow/image2-prompts.json` and `workflow/cover-image2-prompts.json` must record the YouMind GPT Image 2 prompt-library adaptation source when image prompts are written: selected use-case/style/subject axes, structured fields, dynamic slots, storyboard split plan when using explainer-board prompts, and negative constraints. This is method borrowing only; packages must not copy community prompts, creator styles, brands, IP, logos, or exact layouts.
- IP diagram creator plan: when the brief asks for teaching/course/tutorial/explainer visuals, personal IP, creator persona, hand-drawn knowledge card, Agent collaboration diagram, course/PPT/livestream page system, native IP diagram generation, native-final IP diagram video, or other `ip-diagram-creator` routing, `workflow/ip-diagram-creator-plan.json`, `workflow/ip-diagram-creator-native-jobs.json`, and `workflow/ip-diagram-layout-audit.json` must exist. The plan must record `sourceRepo`, `sourceCommit`, active state, activation signals, `plannerDriver`, `plannerRole`, execution modes including `native-final-video`, native direct-use policy, native-final visual-engine ownership, character visual DNA, role-asset authorization/storage policy, scene assignments, prompt contract, user choices for `makePersonalIp` and `addHandDrawnImageAnimation`, stable full-screen page contract, and QA checklist. Native jobs must record MIT/source snapshot metadata and one prompt/repair job per active design scene when active. Layout audit must pass with reserved CSS grid areas for persona, problem, flow, evidence, center, action, and Agents; IP diagram frames must not rely on overlapping absolute-positioned cards. When `primaryPlannerRoute` is true, the plan must also include `directorPlan` and one `pageCards` entry per design scene, and `workflow/design-plan.json` pages must be marked with `primaryVisualSystem: "ip-diagram-creator"`. If `native-final-video` is selected, pages must also be marked `ipDiagramCreatorNativeFinal: true`, `visualEngineOwner: "haloshin/ip-diagram-creator"`, and the rendered frames must be full IP diagram pages rather than a blend with the current framework headline/body card layout. Project-specific role assets stay inside the generated output package and must not be copied into the public Skill package.
- IP diagram stable full-screen page: when native generated pages are consumed as final frames, `logs/qc.json` must pass `ipDiagramFullScreenStable`, `ipDiagramNoBorderWrapper`, `ipDiagramBaseImageStable`, `ipDiagramNoPerCueCropPanZoom`, and `noVerticalBackgroundJump`. The final frame must not show an inset page, card wrapper, drop shadow, matte, border, browser-like frame, or any per-subtitle crop/zoom/pan/y-offset/scale change on the base page. Hand-drawn animation is allowed only as a foreground layer that does not move, crop, redraw, or cover the base page or subtitles.
- Generated image purpose fit: every scene must include `visualAssetDecision`. A generated bitmap may be inserted only when the decision gives it a clear scene purpose, placement, and fallback; if the decision says not to use a generated image, the selected asset must remain deterministic local SVG/MG/chart/design output even when generated images are available.
- Image2 explainer-board fit: when `visualAssetDecision.explainerBoard.active` is true, prompts and manifests must state that the bitmap is a storyboard/source plate under deterministic text layers. It must forbid dense readable generated text, pseudo text, random letters/numbers, copied named styles, logos, and exact source layouts, and it must reserve title/subtitle safe zones.
- Visual preset lock: when any Image2 explainer-board scene is active, `workflow/visual-preset-lock.json` must include `image2-explainer-board-v1`, active scene ids, render contract, prompt/text ownership contract, and reject list. `scripts/validate-image2-explainer-board-routing.mjs <out>` must pass for this route.
- Generated image composition: generated images are supporting scene material. They must not replace deterministic style signatures, MG panels, platform overlays, motion notes, captions, or other planned HTML/SVG/CSS design layers; those layers must stay visible without covering the image subject or subtitle band.
- Frame layout overlap and copy integrity: `workflow/frame-layout-overlap-audit.json` must pass for html-video renders. Headline, body, and subtitle boxes must not intersect visual proof panels, charts, generated-image plates, MG panels, template-driven scene motion boards, platform overlays, or motion-note layers. Internal proof-panel cards and template scene boards must also not overlap each other. Visible text inside cards, panels, captions, caption cue text, scene motion boards, and proof blocks must be fully visible, not clipped, ellipsized, hidden by overflow, or pushed off-canvas. Layout pressure must be solved by reflow, typography scaling, density reduction, scene splitting, or sequential cues, not by cutting a sentence.
- Final-frame viewer chrome: final video frames must not show page numbers, scene counters, section counters, renderer names, framework/library names, capability names, or technical implementation badges. These belong in workflow artifacts, scorecards, manifests, and review HTML outside the simulated video frame, not in the MP4 pixels.
- Visual rhythm: `workflow/visual-rhythm-plan.json` exists and passes. A narration scene may keep one semantic image, but it must not hold one unchanged visual through the whole segment; long scenes need visible crop/focus/scan/detail changes or must be split/given another asset. Exception: complete native generated teaching pages, PPT pages, and `ip-diagram-creator` native-final frames must stay full-screen and fixed; for those pages, rhythm must come from page changes, foreground hand-drawn marks, progress strokes, highlights, reveal masks, or subtitles, not from moving the base image.
- Captions: `.srt` file exists and readable safe-area captions are visible in frames; scene-summary text alone does not count as subtitles for a long口播 video. Caption line wrapping must not create extra TTS cuts; every audio cue should remain a complete sentence or complete semantic beat. If a complete audio cue is visually wrapped, the wrapped lines must appear sequentially as one-line subtitle cues, never stacked together in the same timestamp. Run `scripts/validate-subtitle-cover-contract.mjs` against final output packages that include narration, subtitles, and covers.
- Short-form retention: explicit vertical short-form packages must include platform profile evidence, first-frame promise, first-3-second hook, 2-4 second visual-state beat cadence, mobile-readable caption policy, top mobile status/navigation safe area, and a closing payoff loop in the generated requirements/plan artifacts. These packages must write `workflow/short-form-hook-plan.json`; it must record the first-frame promise, 0-3s proposition, first-three-second visual-state beats, roughly 10-second structure, motion template choices, per-scene Image2/aesthetic decisions, deterministic text ownership, caption-safe policy, top safe-area policy with at least `220px` reserved on `1080x1920`, and payoff loop. Horizontal hook/opening scenes use `workflow/visual-rhythm-plan.json` and `workflow/motion-template-selection.json` instead of this vertical short-form plan. `logs/qc.json` must pass `shortFormHookPlanPresent`, `firstFramePromiseVisible`, `contentPropositionWithin3s`, `firstThreeSecondVisualDensityOk`, `shortFormImage2AestheticDecisionPresent`, `shortFormPayoffLoopPresent`, and `topSafeAreaReservedForMobileChrome` only when vertical short-form is active.
- Vertical safe area: for `9:16` outputs, captions and critical on-screen text must avoid the bottom platform UI area and side controls. QC must fail when the subtitle safe area is inherited from the `16:9` layout.
- Semantic visual sync: main scene titles, diagrams, and progress indicators must advance according to the same timecode plan as the subtitles. Equal-duration visual scenes are a failure for uneven long narration unless the narration was deliberately produced to match them.
- Cover files: cover images are present, readable at mobile-preview size, match target aspect ratios, and accurately represent the video's promise.
- Cover raster exports: each resolution preset has SVG source plus PNG/JPG raster exports; upload-ready user-facing cover copies live only under the topic-scoped `最终成品/` directory and each file stays within its recorded size limit.
- Video-internal cover: `workflow/cover-design.json.videoInternalCover` exists and its ratio matches the final MP4 canvas; standalone platform covers must not be substituted into the video when their ratio differs.
- Cover click logic: cover image is not merely a title card or PPT slide. It must use the Image 2 integrated-typography cover engine and show a platform-ready click reason through contradiction, curiosity gap, transformation, evidence/reveal, or emotional metaphor.
